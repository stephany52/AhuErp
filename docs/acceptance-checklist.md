Acceptance-чек-лист WPF (Phase 8–12)

Документ описывает ручной приёмочный прогон AhuErp на Windows-стенде после внедрения
Phase 8 (Подписи), Phase 9 (Уведомления), Phase 10 (Полнотекстовый поиск),
Phase 11 (Оргструктура + Замещения) и Phase 12 (Отчёты).

Это **не автотесты** — WPF-проекту в репозитории нужны реальные пользовательские
действия (клики, drag&drop, открытие XLSX/DOCX/PDF). Цель чек-листа — за один
прогон проверить, что фичи всех пяти фаз согласованно работают вместе на одной
БД и не ломают друг друга.

---

## 7. ФИНАЛЬНЫЙ E2E — «Жизненный цикл служебной записки»

Сквозной сценарий, проверяющий, что все 5 фаз согласованы.

```
Шаг 1 (Phase 11) — Подготовка
─────────────────────────────
1. Залогиниться как admin.
2. Создать замещение: Стерликов → Дорофеев на 7 дней с сегодня, Scope=Full.
3. В «Оргструктура» убедиться, что Стерликов — руководитель «Служба ИТО».

Шаг 2 (Phase 7 + 11) — Создание документа
─────────────────────────────────────────────
4. Открыть «РКК» → «+ Документ» → Тип «Внутренний» (служебная записка),
   Заголовок «Замена картриджей в принтерах кабинета 305»,
   Описание «Прошу заменить картриджи Canon LBP6030 в количестве 4 шт.».
5. Загрузить вложение `.docx` с расширенным текстом служебной записки
   (содержащим уникальное слово «канцтовары-2026»).
6. Зарегистрировать (получить номер вида ВН-2026-NN).

Шаг 3 (Phase 11) — Назначение задачи + редирект
─────────────────────────────────────────────
7. Назначить задачу: Исполнитель = Стерликов, Срок = завтра, Контролёр = admin.
8. В журнале аудита проверить два события:
   - TaskCreated (Стерликов)
   - TaskReassigned → Дорофеев (из-за замещения)

Шаг 4 (Phase 9) — Уведомление
─────────────────────────────
9. Перелогиниться как Дорофеев. Бейдж = +1.
10. Открыть «Мой рабочий стол» → видеть карточку задачи в «Назначены мне».

Шаг 5 (Phase 8) — Подписание ПЭП
─────────────────────────────
11. Дорофеев открывает РКК → «6. Подписи» → «Подписать ПЭП»
    с причиной «Принято в работу». ПЭП наложена.
12. В журнале аудита: SignatureAdded (Simple).

Шаг 6 (Phase 8) — Маршрут согласования + автоПЭП
─────────────────────────────
13. Дорофеев нажимает «Согласование» → запустить маршрут «Согласование внутр.».
14. Перелогиниться как первый согласующий (admin / Стерликов в зависимости
    от seed-шаблона).
15. На «Мой рабочий стол» → «На согласовании» — увидеть документ.
16. Согласовать. В журнале:
    - ApprovalDecisionApplied
    - SignatureAdded (Simple) автоматически от согласующего
    - NotificationSent автору о решении

Шаг 7 (Phase 8) — КЭП + блокировка
─────────────────────────────
17. После всех ПЭП admin как руководитель учреждения накладывает КЭП
    с thumbprint `DEADBEEFDEADBEEFDEADBEEF` и причиной «Утверждено».
18. Появляется иконка 🔒 в шапке РКК. IsLocked=true.
19. Попытка изменить «Заголовок» → ошибка lock guard.
20. Сменить статус «Согласован» → «Зарегистрирован» — успех.

Шаг 8 (Phase 8) — Загрузка новой версии + автоОтзыв ПЭП
─────────────────────────────
21. Загрузить новую версию вложения (например, отредактированный .docx).
22. Все ПЭП-записи становятся «Отозвана». КЭП остаётся.
23. В журнале: SignatureRevoked × N (по количеству неквалифицированных).

Шаг 9 (Phase 10) — Поиск по тексту
─────────────────────────────
24. Подождать ≤ 5 мин (тик IndexOutdated) или ручной ReindexAll.
25. «Поиск» → чекбокс «Искать в текстах вложений» → запрос «канцтовары-2026»
    → найти РКК. Сниппет содержит подсветку.

Шаг 10 (Phase 12) — Отчёты
─────────────────────────────
26. «Отчёты» → период «сегодня» → «Реестр исходящих (XLSX)»: документ
    в списке.
27. «Отчёты» → выбрать дело, в которое попал документ → «Опись дела (DOCX)»:
    документ перечислен.
28. «Отчёты» → выбрать наш РКК → «Аудит-выгрузка (PDF)»: PDF содержит
    хронологию: Created → Registered → TaskCreated → TaskReassigned →
    SignatureAdded × 2 (ПЭП Дорофеева, ПЭП согласующего) →
    SignatureAdded (КЭП admin) → DocumentLocked → AttachmentVersioned →
    SignatureRevoked × 2 → ReportGenerated × 3.
29. Hash-chain в PDF непрерывный (каждое событие имеет PrevHash = Hash
    предыдущего).

Шаг 11 — Финальная проверка
─────────────────────────────
30. Закрыть приложение. Снова открыть. Все данные на месте, состояние
    подписей и блокировки сохранилось.
31. Дорофеев / admin не получили лишних уведомлений (идемпотентность
    DeadlineSoon / Overdue не нарушена).
```

## 9. Что НЕ покрыто этим чек-листом

  `IndexOutdated()` после фикса PR #6 проходит все вложения, но без батчинга
  это может быть медленно.
- Локализация интерфейса (всё на русском, но UI тестируется только в `ru-RU`).

## 10. Регресс-критерий приёма

Прогон считается успешным, если:

1. ✓ Smoke (раздел 1) пройден полностью.
2. ✓ Финальный E2E (раздел 7) пройден без ошибок и без застрявших
   уведомлений / задач.
3. ✓ Hash-chain аудит-журнала непрерывен на всех затронутых документах.
4. ✓ Никаких unhandled exceptions в `App.xaml.cs.DispatcherUnhandledException`
   за весь прогон.
5. ✓ Файлы XLSX / DOCX / PDF из раздела 6 открываются и читаются.

При фейле любого из пунктов 1–5 — задокументировать в issue с прикреплённым
скриншотом и стек-трейсом из `Logs/` (если включено логирование) или
`%LOCALAPPDATA%\AhuErp\app.log`.
